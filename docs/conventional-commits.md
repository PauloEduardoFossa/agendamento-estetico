# Conventional Commits

Convenção de nomenclatura para mensagens de commit no Git.
O tipo antes dos dois pontos indica a natureza da alteração.

## Tipos mais comuns

| Tipo | Quando usar | Exemplo |
|---|---|---|
| `feat` | Nova funcionalidade | `feat: agendamento automático de recorrência` |
| `fix` | Correção de bug | `fix: lembrete sendo enviado duas vezes` |
| `chore` | Tarefa de manutenção, configuração, estrutura | `chore: estrutura inicial de pastas` |
| `docs` | Documentação | `docs: atualiza ESTADO.md com módulo 1 concluído` |
| `refactor` | Melhoria de código sem mudar comportamento | `refactor: simplifica lógica de recorrência` |
| `test` | Testes | `test: adiciona teste para regra sexta sim/não` |

## Por que usar

Mantém o histórico de commits legível. Em vez de mensagens genéricas
como "ajustes" ou "correções", você vê um diário claro do que foi feito
em cada alteração — sem precisar abrir o código.
